 SECTION 1 — SECURITY AUDIT
================================================================================

  This section documents all security checks performed on the website
  codebase by Greyplatforms to align with industry-standard web security
  practices.

  ─────────────────────────────────────────────────────────────────────────────
  1.1  PAGE-LEVEL SECURITY HEADERS
  ─────────────────────────────────────────────────────────────────────────────

  All 13 pages were individually verified for the following browser-enforced
  security controls, which protect visitors and the website from common
  web-based attacks:

    [✔]  X-Frame-Options
         Prevents the website from being embedded inside external iframes,
         defending against clickjacking attacks.

    [✔]  Content Security Policy (CSP)
         Defines which resources (scripts, styles, images, media) the browser
         is permitted to load. Restricts untrusted content from executing
         on any page.

    [✔]  Referrer Policy
         Controls how much referrer information is shared when users navigate
         away from the website, protecting visitor privacy.

  Status: All three headers confirmed present on every page.

  ─────────────────────────────────────────────────────────────────────────────
  1.2  JAVASCRIPT SECURITY REVIEW
  ─────────────────────────────────────────────────────────────────────────────

  All custom JavaScript files developed by Greyplatforms were reviewed for
  secure coding practices:

    [✔]  Dynamic code execution patterns reviewed and verified absent
         No use of runtime code evaluation methods that could expose
         the site to script injection.

    [✔]  Safe HTML rendering methods in use
         All dynamic content insertion uses secure DOM construction
         approaches that prevent cross-site scripting (XSS).

    [✔]  Diagnostic output reviewed
         All development-time logging and diagnostic calls removed
         from production code to prevent information exposure.

    [✔]  Input and attribute validation
         URL and attribute values passed through pattern validation
         before being applied to the DOM.

    [✔]  Legacy DOM methods verified absent
         Deprecated browser APIs avoided throughout all scripts.

  ─────────────────────────────────────────────────────────────────────────────
  1.3  EXTERNAL LINK SECURITY (All 13 Pages)
  ─────────────────────────────────────────────────────────────────────────────

    [✔]  All links that open in a new browser tab have been verified to
         include the appropriate security relationship attribute, preventing
         the reverse tabnapping vulnerability where a new tab could take
         control of the originating page.

  Status: All external links across all 13 pages verified and secured.

  ─────────────────────────────────────────────────────────────────────────────
  1.4  CONTACT FORM SECURITY
  ─────────────────────────────────────────────────────────────────────────────

    [✔]  All form input fields reviewed for correct field type definitions
    [✔]  Autocomplete attributes configured on all form fields to prevent
         unintended browser auto-fill behaviour on sensitive inputs
    [✔]  Form structure and submission handling reviewed

 SECTION 2 — CODE QUALITY AUDIT
================================================================================

  This section covers the review of all code for cleanliness, maintainability,
  and adherence to development best practices.

  ─────────────────────────────────────────────────────────────────────────────
  2.1  STATIC CODE ANALYSIS — SONARQUBE COMPLIANCE
  ─────────────────────────────────────────────────────────────────────────────

  All custom JavaScript files were analysed using SonarQube static analysis
  and verified fully compliant prior to delivery.

  All custom JavaScript files developed for the website were included
  in the analysis.

    [✔]  Variable declarations
         All custom scripts use modern block-scoped declarations
         throughout, enforcing correctness and preventing accidental
         reassignment.

    [✔]  Cross-environment global references
         All global browser references use the standardised globalThis
         API for portability across JavaScript environments.

    [✔]  Variable and assignment hygiene
         All scripts verified to contain no unused variables or
         assignments that are not consumed by the program logic.

    [✔]  Function nesting depth
         All functions verified to stay within the recommended maximum
         nesting depth, ensuring readable and maintainable code.

    [✔]  DOM dataset API
         All data attribute access uses the modern dataset property API
         throughout all custom scripts.

    [✔]  String API compliance
         String operations use current standardised methods throughout.

    [✔]  Code footprint
         All scripts verified to contain no dead functions or
         unreachable code blocks.

    [✔]  Regular expression correctness
         All regex literals in custom scripts verified clean with no
         unnecessary or misleading escape sequences.

  Status: All 5 JavaScript files fully compliant. Zero SonarQube issues.

  ─────────────────────────────────────────────────────────────────────────────
  2.2  CSS & STYLESHEET QUALITY REVIEW
  ─────────────────────────────────────────────────────────────────────────────

  All custom stylesheets were reviewed for CSS standards compliance and
  cross-browser compatibility:

    [✔]  Stylesheet verified free of legacy browser-specific declarations
         All styles use current CSS standards supported by modern browsers.

    [✔]  Vendor prefix completeness verified
         All CSS properties requiring cross-browser vendor prefixes
         confirmed present and in the correct declaration order:
           — -webkit-backdrop-filter before backdrop-filter
           — -webkit-mask-image before mask-image
           — position: -webkit-sticky before position: sticky

    [✔]  Responsive stylesheet source audited
         Stylesheet source files verified clean with no duplicate
         selectors or empty media query blocks.

  ─────────────────────────────────────────────────────────────────────────────
  2.3  DEAD CODE & UNUSED CODE REMOVAL
  ─────────────────────────────────────────────────────────────────────────────

  All JavaScript files were audited for code that is no longer in use:

    [✔]  Unused functions identified and removed
         Functions with no active call sites across any page were
         removed to reduce code footprint.

    [✔]  Empty logic blocks removed
         Event handlers and conditional blocks containing no operational
         code were cleaned from all scripts.

    [✔]  Commented-out code removed from JavaScript files
         Commented-out variable declarations and logic blocks removed
         from all script files.

    [✔]  Commented-out code reviewed across all HTML pages
         All 13 pages scanned and verified to contain no commented-out
         markup, developer notes, or inactive code blocks.

  ─────────────────────────────────────────────────────────────────────────────
  2.4  LEGACY & DEPRECATED API REVIEW
  ─────────────────────────────────────────────────────────────────────────────

    [✔]  All JavaScript files reviewed for use of deprecated browser APIs
    [✔]  All deprecated DOM manipulation methods verified absent
    [✔]  Modern equivalents used throughout all custom scripts
